## 필수 요구사항 (기능 구현)

### A. 월렛 출금 API

- **Endpoint**
- POST /api/wallets/{walletId}/withdraw
- 
- **Request Body**
```json
{
  "amount": 10000,
  "transactionId": "TXN_UUID_12345"
}
```

구현 로직

- 특정 walletId의 현재 잔액을 확인합니다. 
- 잔액이 amount보다 크거나 같을 경우에만 출금을 진행하고 잔액을 업데이트합니다. 
- 잔액 부족 시 출금을 거부하고 HTTP 400 Bad Request 또는 적절한 예외 코드를 반환해야 합니다.

- 월렛 잔고 및 출금내역 DB 저장/관리 
  - 월렛 잔액 관리 테이블
    - DB Table 필드 예시 : 월렛ID, 잔액
  - 입출금 내역 테이블
    - DB Table 필드 예시 : 일련번호, 월렛ID, 출금액, 잔액, 출금일시

### B. 멱등성(Idempotency) 보장
○ 요구 사항
■ 동일한 transactionId로 출금 요청이 여러 번 들어올 경우, 서버는 첫 번째
요청만 성공적으로 처리하고, 이후 중복 요청은 잔액을 변경하지 않고 동일한
성공 또는 실패 응답을 반환해야 합니다.

### 동시성 테스트 코드
- 하나의 `walletId`를 대상으로
    - 다수의 스레드가 동시에 출금 요청을 보내는  
      **통합 테스트(Integration Test)**를 작성해야 합니다.
- 테스트 시나리오 예시:
    - 100개의 스레드가 동시에 10,000원씩 출금 요청
    - 최종 잔액이 0원 미만이 되지 않는지 확인
    - 총 출금 금액이 초기 잔액을 초과하지 않는지 확인
